- T0-INIT-CLI-PATH (bugfix): `aidlc init` checks whether `aidlc` is on PATH (a file `aidlc` in a PATH directory, on Windows `aidlc` with a PATHEXT extension) and reports it in a new JSON field `cli`: `onPath`, `command` (`aidlc` when it is on PATH, else `node "<path>/bin/aidlc.js"`) and, when it is not on PATH, `note`. When it is not, init prints `aidlc is not on PATH: run each aidlc command as node "<path>/bin/aidlc.js" <command>, or run npm link in "<path>" to put aidlc on PATH` and its `next` line names `node "<path>/bin/aidlc.js" doctor`. When that path holds `$`, a backtick, `%` or `"`, which a shell can expand or end a quote at, `cli` has no `command`, the note names the checkout in plain text and says to run node with its `bin/aidlc.js`, quoted for the shell, or to run `npm link` there, and the `next` line reads `next: review aidlc.config.json, then run doctor through node as the line above says`. Entry check 1 of the `aidlc-loop` skill and the Commands list of the CLAUDE.md section say to run `node <aidlc checkout>/bin/aidlc.js` in place of `aidlc` (issue 451). `aidlc init` writes the new CLAUDE.md line only into a repository that has no aidlc section.
