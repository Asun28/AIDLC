- T0-ADVISORY-WITHDRAW: `aidlc card withdraw` accepts a candidate whose latest R3 decision is an advisory (non-merge-blocking) block, so the fix goes back through the DoD and its own R3 decision; a latest R3 decision that is a pass or a merge-blocking block still refuses with `R3 decided candidate`. In a git repository with a candidate sha recorded, after such an advisory block `aidlc card next` at SHIP ships nothing while the review checkout HEAD is not the bound candidate: it returns a `wait` on `candidate-moved` with `pollSeconds: 0`, whose narration names both shas, `aidlc card withdraw <id> --cause "<finding>"` and checking out the candidate, and it records no operation, spends no retry and writes no run, instead of spending the no-verdict retry on a stale verdict. A HEAD read that throws ships as before, and so does a candidate whose latest R3 decision is a pass or a merge-blocking block, that has a pass by ruling (its standing decision whatever invocation follows it), or that has no decision (issue 449).
