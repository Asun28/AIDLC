- T0-ADVISORY-WITHDRAW: `aidlc card withdraw` accepts a candidate whose latest R3 decision is an advisory (non-merge-blocking) block, so the fix goes back through the DoD and its own R3 decision; a latest R3 decision that is a pass or a merge-blocking block still refuses with the text that begins `R3 decided candidate`, and a candidate with a ruled pass refuses with that text whatever invocation follows the ruled pass; every other refusal is unchanged. In a git repository with a candidate sha recorded and no ruled pass on the candidate, when its latest R3 decision is such an advisory block, `aidlc card next` at SHIP reads the review checkout HEAD after the R3 gate and before the merge intent, and ships nothing while it is not the bound candidate: it returns a `wait` on `candidate-moved` with `pollSeconds: 0`, whose narration names both shas, `aidlc card withdraw <id> --cause "<finding>"` and checking out the candidate, and it records no operation, spends no retry and writes no run, instead of spending the no-verdict retry on a stale verdict. A HEAD read that throws ships as before, and so does a candidate whose latest R3 decision is a pass or a merge-blocking block, or that has no decision; a candidate with a ruled pass ships as before whatever invocation follows the ruled pass (no HEAD read, no `candidate-moved` wait) (issue 449).
