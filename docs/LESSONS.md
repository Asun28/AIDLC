# Lessons

Durable rules this repository learned from its own review blocks and
incidents. Append-only: one dated line per lesson, written at CLOSE of the
card that learned it, only when a review block or an incident taught a
rule the playbook did not already state. Past lines are never rewritten;
a superseded lesson gets a new line that names it. PREPARE reads this
file once per card.

Format: `- YYYY-MM-DD <card or incident>: NEVER|ALWAYS|NOTE <rule> (source: <verdict, PR or incident ref>)`

## Lessons
- 2026-09-14 T1-LOOP-SKILLS-2: NEVER let a review block spend a build attempt; the ladder counts DoD failures only and reviews keep their own rounds and decisions (source: PR #9 review history, two episodes ended escalation-failed with every finding fixed)
- 2026-09-14 T1-LOOP-LADDER: NEVER edit a card file on main and on its branch in separate commits; write the registry copy on main before branching and sync the branch text to main before the ship, since adjacent-line edits conflict and GitHub runs no pull_request workflow on a conflicting PR (source: PR #10, no check runs until main carried the branch card text)
- 2026-09-14 T1-LOOP-LESSONS: NEVER guard a shared file with a Node file lock when a fenced lease already owns the writer; append-only writes and an idempotent retry are the serialisation, and every review round on a lock protocol found a new corner (source: PR #12 review history, two R3 decisions and five R2 rounds)
- 2026-09-14 T1-LOOP-RESUME: NOTE when a review finding overrules a mechanism the card acceptance names, amend the card on main and merge main into the branch before the next R2 round; the panel reads the card from the base and blocked twice on the stale text (source: PR #13 review history, R2 cycle 2 rounds 1 and 2)
- 2026-09-15 T0-SESSION-IDENTITY-3: NOTE when a card documents an operator recovery path, derive every precondition from the code that performs it (session, host, ownership generation) and name the unsupported cases; recovery text written from the happy path took three R3 blocks across T0-SESSION-IDENTITY and T0-SESSION-IDENTITY-2 (source: PR #14 review history)
- 2026-09-15 T0-BIN-STALE-DIST-4: NEVER spread process.env into the environment of a child a test spawns when the test asserts on a variable's absence; build the child environment at each call and drop every letter case of the variable, since Windows looks variables up case-insensitively (source: PR #15 and #16 review history, R3 decisions of T0-BIN-STALE-DIST-2 and -3)
- 2026-09-15 T0-CARD-TAKEOVER-2: NEVER narrow a read-then-write window one field per review round; when a review probes a window of a store without compare-and-set, state the limit and its recovery in the first candidate, since every round on a window found the next one (source: PR #17 review history, four R3 decisions and 25 findings across T0-CARD-TAKEOVER and T0-CARD-TAKEOVER-2)
- 2026-09-15 T0-SHIP-BASE-SYNC-2: NEVER let text from outside the producer (a filename, a configured base name, a verdict reason, command output) reach the ship output raw; flatten and encode every failure detail once at the single failure helper in the first candidate and prove a merge state from git (MERGE_HEAD) rather than from a line of text, since four R3 decisions across T0-SHIP-BASE-SYNC and T0-SHIP-BASE-SYNC-2 each found the next unencoded site (source: PR #18 review history, 12 findings)
- 2026-09-15 T1-REVIEW-FINDINGS-4: NEVER recover a result by reading a second store from a weaker binding than the first write could carry (a sidecar beside the envelope, a pool request by its reusable key, a failure marker without its request); the artifact written at completion names every binding the recovery needs (invocation, candidate sha, request key and queue sequence) and the recovery settles nothing it cannot match exactly, since eight R3 decisions across T1-REVIEW-FINDINGS to T1-REVIEW-FINDINGS-4 each found the next store read from a weaker binding (source: PR #19 review history, merged under a human ruling)
- 2026-09-16 T1-REVIEW-INPUTS: ALWAYS collect and cap every input of a review dispatch (the candidate diff, the delta, the policy hash) before its first mutation (hand-off, release, pool request, reservation) and re-read the binding after any step that re-reads the record, in the first candidate; two R3 decisions each found the next mutation ahead of the check (source: PR #20 review history, F5 re-raised at decision 2)
- 2026-09-17 T0-ARC-EXTERN-DEP-2: ALWAYS find every reader of the facts a fix changes and land them in one candidate before recording the attempt that pins it, since the pinned candidate is the only thing review sees and a succeeded episode takes no further attempt: the board view recomputed the arc the controller had just fixed, and adding that site afterwards cost a successor card and a second review cycle (source: PR #21, routeAmendment reconcile-then-amend, R2 round 1 and R3 decision 2 each finding the next untested claim of the same acceptance list)
- 2026-09-18 T1-REVIEW-STATS: ALWAYS derive a reported measure from the artifact the loop persists for the event, never from a counter kept for enforcement, from arithmetic over a request time, or from the slice of records the caller asked about; all four R3 findings across two decisions were the same mistake in four places (blocks read from `substantiveBlocks`, which counts only merge-blocking decisions; a round's end read as request plus reviewer runtime, which drops the wait for admission; a family aggregated from one goal's runs; a count read from a plain object, which answers `constructor` from the prototype) (source: PR #22 review history, merged under a human ruling)
- 2026-09-18 T1-REVIEW-INVARIANTS: ALWAYS prove an ordering claim against the boundary every writer of the system passes through, never against a chosen set of injected collaborators: the acceptance-3 spy on the card-run store and the review queue accepted a prompt input read after the verdict schema was written and after the lease was renewed, and only patching the filesystem calls themselves made the regression red (source: PR #23 review history, R3 decision 1 F1)
- 2026-09-18 T0-VERDICT-PROSE: NEVER decide what a truncated artifact is by repairing its tail with a fixed ladder of fixes; read its grammar from the start and let the state the cut lands in decide, since three of the five R3 findings were states no ladder could repair (a dangling colon, a string cut inside an escape, a partial literal or number) and each of them let a nested fragment answer as the whole document (source: PR #24 review history, R3 decision 1 F1-F3)
- 2026-09-18 T0-PLANNING-CLAIMS-2: ALWAYS treat every string that reaches an output line or a hook context (a path, a goal or session id, an error message, a reference to read) as data in the first candidate: quote it, report a failure by code, contain a reference before reading it, and read each git pathname on its own; 24 R3 findings across two decisions each found the next unquoted, uncontained or text-bearing string, and two R2 rounds lost to provider read timeouts spent the no-verdict allowance of a cycle, which only a replacement card resets (source: PR #25 review history, merged under a human ruling)
- 2026-09-19 T1-REVIEW-COVERAGE-2: ALWAYS measure from what the producer actually wrote, never from a value some later stage derived from it: across fourteen findings on this feature the same mistake recurred in four places (the join read the citation-enforced verdict instead of the reported one, the entry list after the schema filter instead of the document, one spelling of an item number instead of its value, and the retention of a list nobody asked for), and each one silently changed what the record claimed the reviewer had said (source: PR #24, #26 review history, T1-REVIEW-COVERAGE R3 decisions 1-2 and T1-REVIEW-COVERAGE-2 R3 decision 1)
- 2026-09-19 T1-REVIEW-COVERAGE-STATS: NEVER reuse a measure built for one question as the input to another without re-deriving every tolerance it was given: `roundEndedAt` measures a duration generously, and its request-plus-runtime fallback, its `max` over two clocks and its id-only artifact lookup are each harmless in a wall time and each a wrong answer once the same value orders decisions, which is three findings across an R2 block and the final R3 decision; the corollary four further findings made is that a test pins a rule only when removing that rule alone turns it red, since artifact precedence and a `g-a`/`g-b` tie each satisfied an assertion the rule under test was meant to carry (source: PR #27 review history, R3 decisions 1-2, merged under a human ruling)
- 2026-09-20 T0-WORKTREE-ROOT-DEFAULT: NOTE a successful attempt binds the candidate for good; an R2 advisory note is repaired only through a review block or a follow-up card, since a commit made after the pass is neither reviewable nor shippable under the same episode (`episode already succeeded`) and the card text amended ahead of it makes the reviewed candidate look non-compliant; this card lost two commits and a revert to that (source: PR #29, R2 round 1 advisory, R3 unavailable on a codex quota hold, merged under a human ruling)
- 2026-09-23 T0-R3-FALLBACK-2: NEVER leave a queued request behind when a card switches the reviewer that serves it: a fallback dispatch left the primary's held request in the primary's pool, where the next card's review would admit it once the hold passed and hold the slot with no one to run it, and the empty argv argument the Windows shell drops cost an R3 retry before any review ran (source: PR #31, T0-R3-FALLBACK R3 decision 2, T0-R3-FALLBACK-2 R3 decision 1)
- 2026-09-24 T1-OPUS55-R3-3: ALWAYS run a mutation sweep over every branch a card adds (delete, invert, force true and false, off by one, drop each side of a merge) and add a test for each survivor before the first R3 decision: across T1-OPUS55-R3, -R3-2 and -R3-3, five of six Opus 5.5 R3 decisions found the next rule no test pinned, and the sweep run after the fifth still found eleven survivors (source: PR #32 review history, R3 decisions of all three cards)
