# T1-DOD-RECORD-2

## Deliverable
`aidlc card attempt <card> --outcome success` runs the card's `dod_command` in the card worktree, as the mutant sweep runs it, and stores on the attempt the commit, whether the worktree was clean, the exit code or a timeout, the expected exit, the duration, the output sha256 and the last 4 KB of output. A run with no worktree directory records the DoD as not run, with its reason and without the path. Nothing reads the record to decide anything in this goal; `aidlc card status` prints it and says when the exit differs from `dod_exit`.

## Why
Audit of 2026-11-13, confirmed by the panel on 2026-11-14: the loop never runs a card's DoD (only the advisory mutant sweep does), and a success needs only the worker's non-blank `--dod-receipt` text (card-runner.ts:1161). Owner decision of 2026-11-14: record only in this goal, so the next goal can measure how often the pasted receipt and the real run disagree before any gate reads it. Spec specs/loop-evidence.md R1 to R3, plan plans/loop-evidence.md, order of work item 1.

This card replaces T1-DOD-RECORD, whose run built the candidate this card carries (branch T1-DOD-RECORD at 89e5ea98; its DoD exits 0). Its R4 put the worktree path in the `no-directory` record, so tests/scenarios/t0-flow.test.ts "T1-REVIEW-COVERAGE acceptance 5", which deep-equals the attempts of two fixtures with different worktree paths, fails with it. The owner chose on 2026-11-14 to drop the path from the record (R4) and to add t0-flow.test.ts to the DoD.

Shape. `recordAttempt` is synchronous and the sweep's runner `run` is async, so the shared part is the call (`dodCall`), and the loop runs it with `runSync` and `killTree`, whose helper process runs the same `run`. Because T0-DIRTY-SUCCESS refuses a dirty success before the DoD, a recorded `clean` is `true` or absent, never `false`.

## Acceptance detail

### 1. The status line
For a record with `ran: true`, one line:

`loopDod=attempt <n> exit=<e> dod_exit=<x> <verdict> timedOut=<t> commit=<c> clean=<k> durationMs=<d> sha256=<h>`

`<n>` is the attempt's `n`; `<e>` is `exitCode`, or `none` when it is null; `<x>` is `expectedExit`; `<verdict>` is `matches` when `timedOut` is false and `exitCode` equals `expectedExit`, else `DIFFERS`; `<t>` is `true` or `false`; `<c>` is `commit`, or `-`; `<k>` is `true`, `false`, or `-`; `<d>` is `durationMs`; `<h>` is `outputSha256`. For `ran: false` the line is `loopDod=attempt <n> not run: no-worktree` or `loopDod=attempt <n> not run: no-directory`, with nothing after the reason. With no record on any attempt it is `loopDod=-`.
