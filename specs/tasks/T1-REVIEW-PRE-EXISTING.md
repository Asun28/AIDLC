# T1-REVIEW-PRE-EXISTING

## Deliverable
A defect in code the card did not change blocks the card like one it introduced and spends one of R3's decisions. This card lets a reviewer tag such a reason `[pre-existing]`, in the positions `[question]` and `[suggestion]` already use, and the loop treats the reason as advisory in both stages only when code shows that no cited line is on a changed line of the candidate diff; in every other case the tag is ignored and the reason can still block. It implements spec R14, R15, the `preExistingAdvisory` count of R16, and R21 for its own docs; T1-REVIEW-RESPONSES (split from the same plan item) delivered the dispute kinds and the response counts.

Rule. `changedLineRanges(diff, changedPaths)` parses the committed unified diff: each hunk's new-side range, context lines included, keyed by its `+++ b/<path>`; a hunk with a new-side count of 0 marks the two lines around the deletion; a deleted file, the source of a rename and a changed path the parser cannot match (a path git quotes) count as changed at every line. A tagged reason is advisory only when the location `findingLocation` reads names a file and a line or range, and no cited line is changed. Without a map (the `citedReasonsOf` re-checks at `src/loop/card-runner.ts:1908, 2167, 2280`, the reviewer bench) the tag is ignored, so a reason the classification kept as a block is never downgraded later.

Where. Command path: `enforceCitations`, called by `finalizeReview` (`src/review/pre-review.ts:775`) through `runReviewPanel` from `CardRunner.formalReview` (`card-runner.ts:1576`, diff from 1482) and `CardRunner.preReview` (`card-runner.ts:2134`, diff from 2076); the map rides on `RunReviewPanelOptions` and `ReviewRetentionOptions`, so a rerun of a failed angle on the fallback (T1-EFF-R2-ANGLE-FALLBACK) gets it too. Ship path: `stripAdvisoryTags` in `CardRunner.applyShipResult` (`card-runner.ts:2219`); the diff is collected there with `collectCandidateDiff` on the review checkout, against `run.base?.oid ?? config.base`, pinned to the candidate sha, only when the document carries the tag; a failure or a diff above the cap ignores the tag, so no ship is refused or reclassified for a diff it did not read before. A block carried only by advisory reasons is a pass with the notes, and a ship path that itself refused the merge on such a document stops for a human as it does for `[question]` today.

Retention and count. The advisory reasons already reach `PreReviewRound.advisory`, the verdict files, both decision events, the `review pre` and `review r3` summaries and R3's `## Pre-review advisory notes`. The optional `ReviewInvocation.advisory` keeps the R3 and ship-path decisions' advisory reasons on the card run, so `aidlc review stats` can count, per card and family, every advisory reason carrying the tag (`findings.preExistingAdvisory`), whatever made it advisory; OPERATIONS states that definition.

Prompt and policy. One new prompt line after the balance line, so the pinned order in `tests/surface/r2-pass-notes.test.ts` stays as it is; a new line in both REVIEW.md copies after line 79; `reviewPolicyVersion` moves to `REVIEW.md@5` (T1-REVIEW-CLASS-SWEEP moves it to `@4` first).

Composition. Line numbers are from main at 597e9a2. The loop-efficiency goal (T1-EFF-R3-PROGRESS, T1-EFF-R2-ANGLE-FALLBACK), T1-REVIEW-CLASS-SWEEP (class tags in reason text and on `ReviewFinding`, REVIEW.md, `@4`) and T1-REVIEW-RESPONSES (`FindingStats.responses`, the stats line) change these files first; re-read them at PREPARE and keep what they add.
