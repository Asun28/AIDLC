# T1-SHIP-PUBLISH

## Deliverable
The contract and the `github` implementation of a publish step: push the committed candidate and open a draft pull request, without any other part of the ship. And the one change `ship` needs for it: a draft pull request is marked ready after the CI gate passes and before the merge. No caller yet.

## Why
Intent `intent/execution-gate.md`, proposed outcome 2, owner decision of 2026-11-16: the pull request opens as a draft when R3 is requested, so CI runs while R3 reviews. Today the `github` ship path reads the R3 verdict (github-ship.ts:299) before the push (:354) and the CI gate (:367-403), and CI took 14 to 22 minutes on each of the last 21 pull-request runs. Spec `specs/execution-gate.md` R5, R6 and R9. This card freezes the interface; T1-SHIP-PUBLISH-WIRE calls it.

`publish` checks the pull request before it pushes, as `ship` does (:313-340), so it never pushes to a branch whose pull request is merged or closed. GitHub does not merge a draft, so `ship` marks it ready, and only after `[CI-GATE-PASS]`: the R3 verdict is still read at the start of `ship`, before any of this.
