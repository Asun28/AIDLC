# T1-CARD-READER-CLI

## Deliverable
The one option that runs the card reader by hand or from a script, the configuration key that names its command, and their record in docs/OPERATIONS.md and CHANGELOG.md.

## Why
Spec specs/card-preflight.md R3 and R4. T1-CARD-READER fixed the prompt, the result and the run; this card gives them a command. The coordinator's measurement (plans/card-preflight.md, Order of work, step 4) runs this option from a detached worktree at the commit that first added each case's card, so the option must read the card and the code of that worktree while it takes the reader command from the main checkout's configuration. `cards validate` reads the main checkout's registry whatever `-C` names (sweep), which is why R4 reads the card file from the checkout and R6 keeps the registry checks out of a `--reader` run.

The key and the option are in one card because tests/surface/config.test.ts:586 fails for a key of `aidlc.config.json` that the schema does not carry, and because the key has no reader until the option exists.

## Fixture
A directory from `tmpDir`, made a git repository with `git init -q` (as tests/surface/security-check.test.ts:22). It holds `specs/tasks/T1-X.md`, a card that `parseCardText` accepts with no finding of its own (allow_paths of one file, a dod_command, one numbered acceptance item), `aidlc.config.json` with `cardsDir` and `cardReader` `{ command: ['node', <absolute path of reader.mjs>, '{schema}'], timeoutMs: 20000 }` unless the row says otherwise, and `reader.mjs`, written by the test. The reader stores what it read on stdin, its first argument, its working directory and its pid in files beside itself, then prints one line of prose and the answer the test put in a file beside it, and exits with the code the test put there (0 by default). The child environment is that of security-check.test.ts:24: `PATH`, `SystemRoot`, `AIDLC_STATE_DIR` inside the fixture and `AIDLC_SESSION`. The CLI is started as `node bin/aidlc.js` (`process.execPath` and the path of `bin/aidlc.js`), with a 60 s timeout on each start.

## Output
With JSON output (`--json`, or stdout that is not a terminal) the command prints through `out` the document `{ ok: true, card: <id>, unsupported: [...] }`, the entries as `runCardReader` returned them.

With `--no-json` it prints one line per entry, `<item> | <file>:<line> | <why> | <sentence>`, each field with every run of whitespace replaced by one blank, and then the line `card-reader: <n> named in <id>`. For the two entries of acceptance 3, `{ item: 'R2', sentence: 'The parser shall keep the comment.', file: 'src/a.ts', line: 12, why: 'The function strips it.' }` and `{ item: 'body', sentence: 'The file\nexists.', file: '', line: 0, why: 'No such file.' }`, the three lines are:

```text
body | :0 | No such file. | The file exists.
card-reader: 2 named in T1-X
```

Card reader (cards T1-CARD-READER and T1-CARD-READER-CLI). `aidlc cards validate --card <id> --reader` runs the command of `cardReader.command` once on one card and prints what it names: each sentence of the card about existing code, and each requirement or acceptance item, that the checkout does not support, with its item (`R<n>`, `acceptance <n>` or `body`), file, line and reason. With `--reader` the command reads the card file from the cards directory of the checkout that holds the `-C` directory, else the process directory, runs the reader in that checkout and takes `cardReader` from the `aidlc.config.json` of the main checkout; it does not run the registry checks, and without `--reader` its output and exit code are as before. The result gates nothing: the exit code is 0 whenever the reader returned a valid result, whatever it names. The exit code is 1, with the reason on stderr and nothing on stdout, when `--card` is missing, when the card file is absent, when `cardReader.command` is empty, when the reader cannot be started or does not exit 0, when it runs longer than `cardReader.timeoutMs`, when the last non-blank line of its stdout is not JSON, and when that document is not an object whose only key `unsupported` lists entries of `item`, `sentence`, `file`, `line` and `why`. The argv takes the placeholders `{schema}` (the path of a JSON Schema of the result, which the command writes to `.review/card-reader.schema.json` in the checkout), `{cwd}`, `{card}`, `{effort}` (always `medium`) and `{instructions}` (the prompt; without it the prompt goes to stdin). `cardReader.command` is empty by default and `cardReader.timeoutMs` is 1200000; this repository sets the read-only Codex argv of `formalReview.command`, and `templates/aidlc.config.json` does not set the key. Nothing checks that a reader command only reads.
