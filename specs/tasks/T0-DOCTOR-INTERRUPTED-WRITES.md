# T0-DOCTOR-INTERRUPTED-WRITES

## Deliverable
`aidlc doctor` prints `interruptedWrites`: `none`, or one entry per lock file of a record store whose owner process is not running or unknown, per temporary file of an atomic write whose process is not running or whose name holds no usable pid, per matching path that is not a regular file, and per directory or lock it cannot read, each with its path relative to the state directory, JSON-quoted. The check reads only: it performs no mutation and prints no lock contents, and doctor's exit code does not change. docs/OPERATIONS.md gains one paragraph; the four texts that already claim the check stay as they are.

## Why
Audit item F25b (audit of 2026-11-11 and 2026-11-12), analysed by two consultants and ruled by the coordinator on 2026-11-12, then amended to the coordinator's rulings on a Codex review of the card: CLAUDE.md, templates/CLAUDE.aidlc.md and entry check 1 of both aidlc-loop SKILL.md copies say that doctor checks interrupted writes, and it does not. The ruling makes the statement true with a read-only check instead of correcting the four texts. A lock left by a crashed writer refuses every later write of its record, and today nothing reports it before such a write; the live state of this repository held one from 2026-11-10 to 2026-11-12.
