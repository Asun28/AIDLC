# T1-SHIP-SCAN

## Deliverable
A configured local secret scan on the `github` ship path. `GitHubShipPath.scanCandidate` runs `github.secretScan.command` on the range from the commit `origin/<base>` names to the candidate and returns a receipt `{ base, head }` only for exit 0. A remote-mode ship runs it after the base sync and before its push. Without a command nothing changes.

## Why
Owner decision of 2026-11-17 (approval of the reviewed plan, `intent/execution-gate.md`, Constraints): the early push of T1-SHIP-PUBLISH happens only when a local scan exits 0 on the exact candidate range, with a receipt bound to the candidate and the range; a detected secret blocks publication on both paths; an unavailable scanner gives no receipt. Today the only secret scan of the `github` path is the gitleaks CI job, which runs after the push. This card adds the scan and its use in `ship`; T1-SHIP-PUBLISH uses it before its push.

Exit codes. gitleaks exits 1 for a leak and for an error alike unless `--exit-code` sets the leak code, and a program that cannot be started exits -4058 under the tree kill on Windows (sweep). So the configuration names the finding code, 0 is clean, and every other end of the run is "scanner unavailable". Both push nothing; they differ in the stop reason:

| Scan result | Ship output | Class | Card |
|---|---|---|---|
| exit 0 | `secret scan clean: <base>..<head>`, then the push | as on main | as on main |
| `findingExitCode` | `check-secrets: ...; nothing pushed` (the scaffold's sentinel) | `secrets-blocked` | STOP/risk (card-runner.ts:3178-3181) |
| anything else | `[SHIP-PUSH-FAIL] secret scan unavailable: ...; nothing pushed` | `push-failed` | STOP/tool, final for the card (card-runner.ts:3182-3208) |
| no command | nothing | as on main | as on main |
