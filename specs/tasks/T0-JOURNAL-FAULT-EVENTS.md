# T0-JOURNAL-FAULT-EVENTS

## Deliverable
`CardRunner` (src/loop/card-runner.ts) journals the attempt, R2, R3 and merge-result events of the covered commits only after the record write that commits the decision, and exactly once. That write records the event on the card run as owed (`CardRun.journalOwed`, src/core/types.ts). The command appends it after the write. When that append does not land, the next `card next`, `card attempt`, `review pre` or `review r3` on the card appends it, marked `completed: true`, before anything else. A failed record write no longer doubles `ATTEMPT_STARTED` or `ATTEMPT_FINISHED`, and a failed append no longer loses `PRE_REVIEW_DECIDED`, `REVIEW_DECIDED` or the merge `OPERATION_RESULT`. docs/OPERATIONS.md, docs/ARCHITECTURE.md and CHANGELOG.md state what the journal now guarantees.

## What the journal guarantees
Read at 794624a. The journal is meant to hold these events: ARCHITECTURE item 1 says every card runner action appends one, the audit reads the merge result as the shipped fact, and the liveness check counts them and calls a pin a defect. It also has no mechanism that delivers them, which is why T1-VERIFY-FAULT-POINTS did not require every card-run change to reach the journal ("main has no outbox"); that sentence stays true, because this card covers only the events of R1. The guarantee this card states and enforces: for each decision a covered commit writes to the card run, its event is appended after that write, at most once per key, and at least once by the end of the next of the four commands on the card. The one exception is a merge result whose operation the ledger does not show with that status, which is left to `aidlc ops reconcile`.

## Design

### Write order
- `card attempt`: the R4 appends, then the stored run, then one record write holding the finished attempt and the owed `ATTEMPT_FINISHED` (with the implicit `ATTEMPT_STARTED` when the attempt was not open), then the append section of R2. The BUILD and REVIEW_FIX steps of `card next` do the same with `ATTEMPT_STARTED`. These three use the compare-and-set write (`saveCardRun`), so the record they extend is the persisted one; entries already in the journal may be dropped from it.
- `review pre` and `review r3`: the R4 appends at the start, the review, then `commitReviewed`'s locked write, which records the owed event for whatever status the commit reaches (committed, superseded, stopped, abandoned, fenced; the event's `decision` names the discard as at 794624a) beside the unjournaled entries of the locked record, then the append section. `review r3` first publishes the canonical verdict and adds `canonicalPublished` and `publicationError` to the event it appends there.
- The ship's `merged` or `merge-unconfirmed` result: `finish`'s locked write records the owed `OPERATION_RESULT` (operation, status `succeeded` or `UNKNOWN`, the facts), then `markResult`, then the append section, which appends it only while the ledger shows that status (R5).
- The append section: `GoalStore.updateCardRun` with a change that reads the goal journal once, appends each owed event the journal does not hold, and returns the record unchanged, so nothing is written and appends of two processes never interleave.

### What each failure leaves, and its recovery
- The record write throws: no event is appended, and the work is redone as at 794624a (the attempt still open, the reservation still pending, the operation `issued` after a lost `finish`, H10).
- The append throws, the lock is not taken, or the process dies after the write: the run holds the owed event, and the next of the four commands appends it before any other write.
- An R4 append throws: the command fails with no other write and the run is unchanged; the next command tries again.
- `markResult` throws: the owed result is never appended while the operation is `issued`; a person's `aidlc ops reconcile` journals `OPERATION_RECONCILED`, after which the owed result is never appended (R3).

### Limits
- An event stays owed until one of the four commands runs on the card. Another command (a dispute, a takeover, `aidlc report`) does not append it, and `aidlc audit verify` run before that still misses it.
- While the run holds owed entries, each start of the four commands reads the goal journal once. Entries stay on the record until a later commit drops the journaled ones, so after the first decision every such start reads it.
- A `REVIEW_DECIDED` appended by R4 has no publication fields.
