# T1-VERIFY-MUTANTS

## Deliverable
65 R3 findings in this repository's history were dimension 6 (tests missing or unable to fail), for example "Removing the entire T1-BOUND-TELEMETRY-3 entry would still pass" and "Removing both in memory still passes all four tests". The lesson of 2026-09-24 (T1-OPUS55-R3-3) asks for a mutation sweep over every branch a card adds before the first R3 decision, and no command runs one. `aidlc card mutants <card>` takes the mutants T1-VERIFY-MUTANT-GEN generates for the changed `src/**/*.ts` lines of the card's committed candidate, applies them one at a time, runs the card's DoD on each under a timeout, restores each file from the bytes it read, and writes `<worktree>/.review/<card>.mutants.json` bound to the candidate commit. It is advisory evidence: no gate reads the report and the command exits 0 whatever survives. This card implements spec R17, R18 and R19, and R21 for its own docs; spec R20 (the R3 prompt section) is T1-VERIFY-MUTANTS-PROMPT.

## Limits (stated before the first review)
- On Windows a timed-out DoD's shell is killed (`src/probes/exec.ts:91`), not the node process it started, so a hung mutant can leave a node process running after its file is restored. The mutant is recorded `timeout`. Card T0-EXEC-TREE-KILL (a timeout on Windows kills the whole process tree) is the fix; this card does not touch `src/probes/exec.ts`.
- A commit made while a mutant is applied (an interrupted run followed by `git commit -a`) can commit a surviving mutant. The marker names the file and `--restore` repairs the working copy; T1-VERIFY-MUTANTS-PROMPT makes `aidlc card attempt` refuse while the marker exists.
- No lease check: another session editing the worktree during a sweep changes DoD outcomes. The per-file guard (R7) and the HEAD check (R11) catch a change to the file under mutation and a commit, not edits to other files.
- Each run overwrites the report: one report per card, bound to one candidate.
