# T1-REVIEW-CLASS-SWEEP

## Deliverable
In 25 of the 28 cards whose two R3 decisions both blocked, the second block named a REVIEW.md dimension the first block had already named: the repair fixed the cited site and left the other sites of the same class (T1-BOUND-TELEMETRY-2: decision 1 found `REVIEW_DECIDED` appended before the ship-result bound stop is saved, decision 2 a failed `PLAN_INVOKED` append that prevents saving the exhausted planning counter). `docs/LESSONS.md` lines already reach the prompt as "Learned invariants" and ask for every site of a learned class. This card does the same for the current block: the reviewer names the class of each block reason, the finding records it, the repair directive lists each class with its sites and asks for every site inside `allow_paths`, and the next round or decision checks that every site was fixed.

Decisions:
- Tag. `(class: <slug>)`, read by `findingClass(reason)` in `src/core/review-policy.ts` the way `findingReference` reads `re:F<n>`: anywhere in the reason, the keyword `class:` case-insensitive with at most one space after the colon, the first `(class:` group deciding. The slug is lowercase letters and digits in dash-separated runs (`^[a-z0-9]+(?:-[a-z0-9]+)*$`), at most 40 characters, with the pattern and the limit in `src/core/types.ts`. A malformed slug records no class and the reason is recorded as it is without the tag. The prompt and REVIEW.md ask for the tag right after the dimension and before the `@ <file:line>` location, so `ADVISORY_TAG`, `citedReason` and `findingLocation` read the reason unchanged; a `[question]` or `[suggestion]` reason carries no class, because a class between the axis tag and an advisory tag would hide the tag.
- Record. `ReviewFinding.class` is optional, parsed with the slug pattern; records written before this card parse unchanged. A new finding takes the class of its reason. A re-raise that carries a class sets it on the re-raised finding when that finding has none (a finding raised before this card, or untagged) and never replaces an existing class; the re-raise reason, kept in `reraised[]`, keeps the tag as text, so `reraised[]` gains no field. The class changes no id, disposition, revision, resolution, counter or decision.
- Directive. Narration only, no change to the `CardDirective` type: nothing outside `card-runner.ts` reads a directive field other than the narration, and the REVIEW_FIX repair that this repository's command R3 path returns is a `build` directive with no `reasons` field. A pure `blockClasses(findings)` groups the open findings of the block (`findingsOfBlock` on the blocked candidate) by class with their ids and cited sites; one helper turns it into the text appended to the three formal repair narrations (card-runner.ts:614-634, :1227, :2449 at 597e9a2): the class list, then a request to fix every site of each class inside the card's `allow_paths`, not only the cited lines, and to leave a site outside `allow_paths` unchanged and dispute a re-raise that cites one. A block without a class appends nothing.
- Prompts. One class line in both stages, placed right after the verdict-balance line so the pinned order of the reasons, advisory-tag, pass-notes and balance lines holds. `VERDICT_CONTRACT` stays byte-identical, as T1-REVIEW-INPUTS added `[question]` and `[suggestion]` in a separate line and left it alone; the verdict schema is frozen. `PriorFinding` gains `class`; `## Prior findings` names it, and an open finding with a class asks the reviewer to check every site of that class in the candidate and to re-raise with `re:F<n>` once per remaining site. Disputed and deadlocked lines name the class and keep their instruction: the author has contested them.
- Policy version. REVIEW.md's output contract gains the class sentence, so both configs move to `REVIEW.md@4`, as T1-REVIEW-INPUTS moved them to `REVIEW.md@3` when it added the advisory tags (its acceptance 5, asserted at tests/surface/templates.test.ts:186). The version is part of the review admission key: a pass recorded under `REVIEW.md@3` stays valid for its candidate only.

Composition with the loop-efficiency goal, which runs first. T1-EFF-R3-PROGRESS changes the R3 stop rule in `review-policy.ts`, `types.ts` and `card-runner.ts` (a block of only new findings gets another repair round; a repeated unresolved finding stops for a ruling). This card reads that rule and changes none of it. A remaining site cited with `re:F<n>` is a re-raise like any other and counts toward that rule exactly as an untagged re-raise does (acceptance 2 and 7). The class text is appended after the narration that card leaves. Line numbers in this card are from main at 597e9a2; PREPARE re-reads every cited site and re-greps `kind: 'review-fix'` and `case 'REVIEW_FIX'` for any repair directive that card added.
