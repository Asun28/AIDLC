# T1-REVIEW-BENCH

## Deliverable
`aidlc review bench run --stage <pre|formal> [--dir evals/review] [--case <id>] [--include-unconfirmed]` scores the stage's configured primary reviewer on the cases under `evals/review/`: each candidate is reviewed once, as the loop reviews a first round or a first decision, in a detached temporary checkout that is always removed; a bug case is a hit when a cited block reason lands inside an expected window, a clean case is a false block when the review blocks, and the report gives recall, the false-block rate and the no-verdict count. It never runs in CI, never touches a card run and never blocks a card. The docs state the case format, how a person confirms a case, and the practice of running the bench before and after a reviewer change.

This card is the run half of plan item 3 and implements spec R6, R7, R9 and R21 for its docs. Spec R8 (`review bench export`, the pin refs) and the export half of spec acceptance 3 move to a follow-up card, T1-REVIEW-BENCH-EXPORT, to be added to the plan before T1-REVIEW-CLASS-SWEEP.

Decisions:
- Base: the case stores the base commit. The card runs record only `base.ref` (`main` in all 157) and, in 9 runs, `base.oid`; findings record `candidateSha` alone. The base is `git merge-base <base.oid, else base.ref> <candidate>`, the commit the loop's three-dot diff started from; for 13 of the 160 candidates `main` gives another commit than the recorded oid, so the oid wins when present.
- Card text: read from `card.path` at the candidate commit (the temporary checkout), not embedded. The sha pins it as firmly as embedded text would, a case stays short enough to write by hand, and all 160 candidates carry their card file. The reviewer in the loop read the main checkout's copy at review time; the candidate's copy differs from it only by the card's own edits to its file, which the diff shows anyway.
- Version under test: `REVIEW.md`, `aidlc.config.json` and `docs/LESSONS.md` come from the root of the checkout the command runs in, where the loop reads the main root. Run in the main checkout this is the loop's input; run with `npm run dev -- review bench run` in a card worktree it scores that card's prompts, policy and config, which is how a reviewer change is scored before and after.
- Temporary checkout: `git worktree add --detach` in a fresh directory under the OS temp directory, never under the state directory, removed in a `finally` block.
- Retention: reviewer logs and verdicts go to `.review/bench/` of the checkout root (gitignored), named in the report.
- Exit code: 0 for any report without a leftover checkout, 1 for a refusal before any review or a leftover checkout; the scores never change it.
