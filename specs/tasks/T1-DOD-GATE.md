# T1-DOD-GATE

## Deliverable
`aidlc card attempt <card> --outcome success` no longer records a success that the loop's own run of the card's DoD refutes. When that run exits with another code than `dod_exit`, times out or gives no exit code, the attempt is a counted failure with the DoD result as its cause, the record stays on it, and the card stays in BUILD. A DoD that did not run, and one that met `dod_exit`, are recorded as today.

## Why
Owner decision of 2026-11-16 (`intent/execution-gate.md`): a refuted success is a counted failed attempt. Since T1-DOD-RECORD-2 the loop runs the DoD on every success and stores the result, and nothing reads it: a candidate is ready when the worker's own receipt text is present (card-runner.ts:849-850; GitHub issue 124, "The DoD receipt of a card attempt is self-attested text"). On 2026-11-16 all 25 recorded loop runs met `dod_exit`, so the gate is expected to change no outcome of a truthful worker. Spec `specs/execution-gate.md` R1 to R4.

The same-cause rule applies as it stands: two refuted successes in a row whose causes are equal after `normaliseCause`, neither with `--progress`, end the episode with `same-cause-stop`. Every number reads as `N`, so two different exit codes are one cause; an exit code and a timeout are two causes. A timed-out DoD is therefore also bounded: two in a row stop the card. The recorded maximum is 234 s against the 540 s limit.
