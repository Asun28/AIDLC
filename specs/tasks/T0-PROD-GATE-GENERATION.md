# T0-PROD-GATE-GENERATION

## Deliverable
The `production-gate` hook honours a production authorization only on a goal that is not terminal and not in DONE or STOP, and only when the goal's first record matching the reference, the record main matches, was granted in the goal's current generation; an absent `goalGeneration` counts as 0. Every command the gate denied on main it still denies. Every authorization the controller newly records stores `goalGeneration`. A refused approval gets the gate's exit 2 in the pass whose pattern sees the command when no earlier guard blocked, and a command whose approval the gate admitted before and now refuses is denied by the gate in the first pass where another guard's denial was returned before. After a resume the operator names the new production authorization by its id or a new `--ref`. `aidlc release next` is unchanged.

## Why
Audit item F20, analysed by two consultants and ruled by the coordinator on 2026-11-12; the draft was reviewed by Codex and amended to the coordinator's rulings. On main the gate admits a raw production deploy for an authorization of a goal that is DONE, cancelled or stopped, and after `aidlc goal resume` every earlier production authorization counts again in the new generation, so an approval for an earlier candidate admits a deploy that needs fresh authority (`docs/plans/PLAN-aidlc-loop.md`:395, LC6: a yes for an earlier failed candidate is insufficient). The gate cannot tie a shell command to a candidate; the goal generation is the part of that rule it can check.
