# T1-VERIFY-MUTANT-GEN

## Deliverable
The first of three cards for spec R17 (the mutant report for R3). It adds `src/review/mutant-gen.ts`, a pure module with no new dependency: `changedSourceLines` lists the new-side lines a zero-context diff adds to `src/**/*.ts`, `mutantsFor` lists the mutants of those lines under eight fixed operators while an in-house scanner keeps comments, strings, template literals and regex literals out of reach, and `applyMutant` writes one mutant into the source text. T1-VERIFY-MUTANTS runs the mutants under the card's DoD and writes the report; T1-VERIFY-MUTANTS-PROMPT hands the survivors to R3. This card implements the generator part of spec R17 and R21 for its own docs.

## Notes for PREPARE
- Line numbers are from main at 597e9a2; the loop-efficiency goal merges first. Re-read every cited line at PREPARE.
- Tokenizer. `typescript` is a devDependency and the published package depends only on `@anthropic-ai/sdk`, `commander`, `yaml` and `zod`, so `ts.createScanner` is not available where `src` runs; Node's type stripping gives no token positions. The scanner is in-house and reads the whole file once (block comments and template literals span lines). Regex rule: a `/` that opens neither `//` nor `/*` opens a regex literal when the previous code character is absent or one of `( , = : [ ! & | ? { } ; + - * % < > ~ ^`, or the previous word is `return`, `typeof`, `case`, `do`, `else`, `in`, `of`, `new`, `delete`, `void`, `throw`, `instanceof`, `yield` or `await`; otherwise it is division.
- Operators against the lesson's list (delete, invert, force true and false, off by one, drop each side of a merge). Delete: `drop-statement`. Invert: `negate-equality`, `swap-logic`, `drop-not`. Force true and false: `force-true` and `force-false` on `if` conditions, and `flip-boolean`. Off by one: `boundary`. Drop each side of a merge: not covered, since the operand boundaries of `??`, `||` or a spread need an expression parser; `swap-logic` covers the `&&` and `||` merge of two conditions. The two R3 dimension-6 quotes this targets ("Removing the entire T1-BOUND-TELEMETRY-3 entry would still pass", "Removing both in memory still passes all four tests") are deletions, which `drop-statement` makes.
- Why `if` conditions and not returned expressions: whether a returned expression is boolean needs types, and a non-boolean forced to `true` is a type error the typecheck kills without saying anything about the tests. Why whitespace on both sides of a binary operator: `<` and `>` in generics (`Promise<void>`, `Record<string, X>`) are common in this codebase, and each would cost a full DoD run to be killed by the typecheck.

## Limits (stated before the first review)
- A file whose path git quotes (control characters, a double quote or a backslash in the name) is skipped, not decoded.
- The regex rule misreads a regex literal after `)` (read as division) and a division after `}` (read as a regex). A misread adds or drops a mutant; it never changes a restore, which the runner card does from the bytes it read.
- A comparison written without spaces (`a<b`) is not mutated; this repository's style puts spaces around binary operators.
