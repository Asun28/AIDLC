## Limits (stated before the first review)
- A timed-out DoD ends with its whole process tree: `run` has done that since T0-EXEC-TREE-KILL merged, so this card adds nothing for it and does not touch `src/probes/exec.ts`. The mutant is recorded `timeout`.
- Source files are written in place with `writeFileSync`, which keeps the file mode; `atomicWriteText` takes only text and `src/state/store.ts` is outside this card's paths. A process killed inside that write can leave a file that holds neither the original nor the mutant, which `--restore` refuses; the marker still holds the original bytes in base64.
- A commit made while a mutant is applied (an interrupted run followed by `git commit -a`) can commit a surviving mutant. The marker names the file and `--restore` repairs the working copy; T1-VERIFY-MUTANTS-PROMPT makes `aidlc card attempt` refuse while the marker exists.
- By the user's ruling of 2026-11-06 a DoD that sets out to reach outside the worktree is out of scope: it runs as the user and can write anywhere itself. R14 and R16 stop this command from following a path out of the worktree, whether a candidate committed that path or a DoD left it there by accident, and they are not a sandbox.
- A source with more than one hard link is refused even when every name is inside the worktree, since `lstat` gives the count of names and not where they are.
- Each parent check runs in the same synchronous step as its read or write, so a DoD run cannot put a link between them; another process racing that step is not stopped, since Node has no walk that opens each parent without following links and this card takes no lease.
- No lease check: another session editing the worktree during a sweep changes DoD outcomes. The per-file guard (R7) and the HEAD check (R11) catch a change to the file under mutation and a commit, not edits to other files.
- Each run overwrites the report: one report per card, bound to one candidate.
