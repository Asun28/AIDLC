# T0-ADOPT-EXTERNAL-MERGE

## Deliverable
`aidlc card adopt-merge <card> --pr <n>` records a merge that happened outside a ship operation of the loop. It confirms from gh that PR `<n>` is a PR of the card's branch into the base and is MERGED there, with its head and merge commit, and from git that the merge commit is on the fetched base. It then sets the run's `mergeVerified`, moves the run to CLOSE (removing a STOP), and journals `MERGE_ADOPTED` with the facts, so `aidlc card close` and the goal's CLOSE work as for a card the loop shipped.

## Why
Issue 358: a goal with two cards merged outside the loop passed `arc-verified`, which counts registry status `merged`, and then stuck in CLOSE, which needs each run's `mergeVerified`. `card close` refuses a run without it, and nothing outside a ship operation sets it. The owner chose gh-verified adoption over CLOSE trusting the registry status, so the merge is evidenced by gh and git, not by a text field.
