# T1-SHIP-PUBLISH-WIRE

## Deliverable
`aidlc review r3 <card>` pushes the candidate and opens its draft pull request through the ship path's `publish` step before it requests the review, once per candidate, so CI runs while R3 reviews. The result is stored on the card run. A publish that fails or throws changes nothing about the review.

## Why
Owner decision of 2026-11-16 (`intent/execution-gate.md`, proposed outcome 2): the draft pull request opens when R3 is requested. On the `github` ship path the push comes after the R3 verdict today (github-ship.ts:299 before :354), and CI took 14 to 22 minutes on each of the last 21 pull-request runs, all of it after the review. Spec `specs/execution-gate.md` R7 and R8.
