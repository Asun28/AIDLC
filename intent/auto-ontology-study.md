# Intent: Card the practices of the NVIDIA/auto-ontology review that this repository's records support
Author: asun28 (owner); drafted by the coordinator session. Status: accepted.

## Problem
The owner asked on 2026-11-23 for the results of a Claude Fable 5.2 review of
`github.com/NVIDIA/auto-ontology` (commit f3c310c7; the reviewer read it and did
not run it) to be planned, discussed and turned into cards or issues.

The review finds no code this repository can use and proposes three practices:
a control-arm report generated by CI (P0), a check of what the documents claim
against the code (P1), and review rules selected by path (P2). Its figures about
auto-ontology are leads, not evidence, and this session did not read that
repository. Each proposal is checked below against main at b9e10702.

## Proposed outcome
1. P0: the two baseline cards are amended while unstarted. Each records its
   change in `changelog.d/<card id>.md`. Each run record carries the SHA-256 of
   `evals/baseline/tasks.json` as the run read it, and the generated report
   names it. A job of the `ci` workflow runs
   `node evals/baseline/analyze.ts --check`. The owner opens their goals after
   the sandbox repository exists and the trial machine has the JDK and Android
   SDK.
2. P1: no card. Issue 420 records the probe and the count that would reopen
   the proposal: the document pins by kind (a name, or text) and the card
   amendments a pin caused since 2026-11-17. Issue 419 names the two commands
   no document mentions.
3. P2: no card. Issue 421 records the proposal, the evidence above and the
   paired measurement that would reopen it.

## Affected users and systems
The two baseline cards under `specs/tasks/` and `docs/plans/PLAN-v5.1-hardening.md`,
and through the cards `.github/workflows/ci.yml`, `evals/baseline/` and
`changelog.d/`. The issue tracker of `Asun28/AIDLC`. No file under `src/`, no
prompt and no loop behaviour changes by this intent.

## Constraints
- Outside figures are leads, never evidence.
- No existing test is weakened or removed. Retiring a pin is not in scope.
- Plan decisions D1 to D3 of the baseline cards stand: task repository
  `Asun28/MyInspection`, the private sandbox `Asun28/aidlc-baseline-sandbox`,
  10 USD per run and 500 USD in total. No second agent arm is added.
- A card whose run has started is not touched; both baseline cards are `todo`.
- No change to the R3 prompt, to `REVIEW.md` or to the allowance constants.

## Decisions (owner, 2026-11-23, in the session)
- Q1, P0: amend both baseline cards as outcome 1 says. The digest is taken per
  run and not from the working tree when the report is written, since only the
  first shows which task list the runs used; that reading of "a digest of the
  task set" is the coordinator's. The CI check is a job of its own,
  `baseline-report`, because `tests/surface/ci-shard.test.ts` pins the run
  steps of the `check` and `check-windows-shard` jobs whole. It is not a
  required check; making it one is the owner's change to the ruleset and to
  `github.requiredChecks`.
- Q2, P1: two issues and no card (issues 420 and 419). The question put to the
  owner named `aidlc card cleanup` and `aidlc ops intent` as the commands no
  document mentions; a check after the answer found `aidlc op intent`, the
  alias, in `docs/DELIVERY-OPS.md` and `release.md`, and found `aidlc card start`
  in no document. Issue 419 names `card start` and `card cleanup`.
- Q3, P2: one issue, deferred, and no card (issue 421). The keep rule of a
  later measurement is the owner's to set before the run.
