# Changelog

## Unreleased

- Lessons in the loop, card T1-LOOP-LESSONS: `src/artifacts/lessons.ts` owns the frozen line format and the append-only file (created from an embedded header when missing, the template placeholder giving way to the first lesson); PREPARE carries `lessons` (file, count, most recent lines); the file is created exclusively and only ever appended to, one literal line per lesson, with calendar dates, one-line fields and the same validation for parsing, reading and writing; closure flags are fenced, serialised by a lessons lock, refused for a terminal or re-generated goal and for any raw card patch (which sets neither closure nor DONE), and accepted for a CLOSE run only (CLOSE renews or takes over the card lease, and DONE records that predate the predicate stay DONE through the state evidence while the schema default stays false), a lesson is journaled before the file changes and a retry reuses that pending line, so a completed append is recognised even across a date rollover and no writer overwrites another (every write is an append); `closure.lessons` is the sixth closure predicate, recorded by `aidlc card close --lesson "<NEVER|ALWAYS|NOTE> <rule> (source: <ref>)"` or `--skip-lesson "<why>"` (commander reserves the `--no-` prefix for boolean negation, so not `--no-lesson`), both journaled as EVIDENCE_RETAINED; `--all` leaves it open.
- CI gates in the loop, card T1-LOOP-GATES: the gitleaks history scan is a blocking job in both workflow copies; a failing check run named for a secret or security scan, or raw gitleaks output, is the CI class `security` (never rerun, STOP/risk); `aidlc.config.json` gains `github.requiredChecks|requireVerdict|ciTimeoutMs|ciPollMs`, passed to the GitHub ship path through `shipPathFor`, where a required check absent from the head is pending, never satisfied, and every reported check must succeed. This repository requires its four unconditional check runs. The GitHub gate lines carry the check runs as JSON with brackets encoded, so a name with newlines, commas or sentinel-like text survives and never enters the sentinel stream, and the runner classifies those failures from the structured checks alone (a pending name is no evidence; a green scan next to a red build is a code defect; every red gate line counts; Unicode line separators in names are escaped; plain name=conclusion pairs are still read and an unparsable red pair-like line naming a scan fails closed); a required check that reports skipped or neutral fails the gate; `secret_scan` spellings count. `github.requireVerdict` false is refused next to `gateRequired` true, and a block verdict for the candidate fails the ship even when the requirement is waived.
- Review budgets independent of the build ladder, card T1-LOOP-LADDER: a review block (R2 round or R3 decision) reopens the effort episode without converting the blocked attempt into a counted failure; `countedAttempts` counts DoD failures only, attempt numbers stay sequential, and the same-cause and escalation rules are unchanged for real failures. Reviews keep their own budgets (rounds per R3 cycle, two R3 decisions). Found when two cards of the loop-integration goal ended by the ladder while every review finding was accepted; the first line of `docs/LESSONS.md` records it. Not-counted records after a block never hide the reopened success, and a preserved success between two same-cause failures breaks the streak while the DoD-failure count stays cumulative.

- Skills in the loop directives, card T1-LOOP-SKILLS: every routing result and directive carries `skills` (`diagnose` on bugfix and incident routes, `grilling` on T1/T2, `tdd` on every card-loop route; the `[route]` line prints `skills=`); `aidlc goal new --intent <file>` records the intent on the goal and the T1/T2 plan directive lists its open questions for the grilling skill (a missing file is narrated, never thrown); the build directive names `tdd`, plus `diagnose` on a bugfix goal or a card with `diagnosis:`; PREPARE points at `docs/LESSONS.md`; a merge conflict at ship (git's or GitHub's own diagnostic on a line of the ship output, never a card id, a resume command or quoted text) returns the card to BUILD naming `merge-conflicts` with the DoD receipt cleared, the effort episode reopened and the repair persisted as `CardRun.pendingRepair` until the next successful attempt (a failed repair keeps it), so a resumed worker still gets the skill; when the episode cannot admit a repair attempt (judged with the justification BUILD grants) the card stops with reason `card`, and after the card deadline with reason `time`; a rejected RED receipt is remembered so the scaffold worktree cannot reload it; other merge failures keep the tool stop; `red-missing` reopens the episode the same way and clears the rejected RED receipt. Every build directive, including the review-fix repair, names the skills. Skills follow the finalized size as well as the kind (an explicit T0-bugfix card route names `diagnose`, explicit T1/T2 card routes name `grilling`). An intent file that does not validate is narrated as such (by problem category, never a parser excerpt that could carry a front-matter value), never as an empty question list.

- Review panel and review guards, card T0-R2-PANEL: `preReview.perspectives` runs one reviewer process per angle concurrently and aggregates into one round verdict (quota-hold > block > no-verdict > pass; reasons tagged with the angle; the round document is always retained); the formal review stays one exhaustive pass per decision. The R3 prompt now demands every material finding in one pass (adversarial stance) instead of a brief answer. A deterministic scope gate blocks changed paths outside `allow_paths` before any model call. Citation rule in code: a block reason without an axis tag and a diff location is advisory, never blocking. This repository runs R2 as three contract-bound angles (ac-coverage, spec-deviations, edge-cases) and R3 as one exhaustive Codex pass. Guards from the second Codex decision: no review runs once the allowance is used or the card is stopped, a verdict naming another branch is stale, a ship-path re-read of a command verdict is never a second decision, a non-zero reviewer exit or a self-reported failure never passes, the canonical verdict file is published only for a successful non-stale decision, the invocation is reserved before dispatch and state is re-read after it (a STOP saved meanwhile is kept), the formal review takes a shared-pool slot, HEAD must be the pinned candidate, dynamic instructions never pass through a shell, perspective names are validated, changed paths are collected NUL-separated and the diff with --text so a file that was binary on the base still shows its hunks, a reviewer angle that fails to spawn is a failed receipt rather than an aborted round, an advisory block is published as a consistent pass with every finding under advisory, review guards read the persisted run and fence the lease before reserving, source files no longer contain NUL bytes (git diffed them as binary, so R2 never saw the review module); a quota hold is timed from the clock after the review returns, since a review can outlast the hold it reports (found by the R2 edge-cases angle on this card). Cards no longer pre-set `status: merged`.

- Formal review (R3) as a command, card T0-R3-COMMAND: `aidlc review r3 <card>` runs `formalReview.command` (Codex `exec` with a materialised verdict schema in this repository; argv placeholders `{instructions} {base} {head} {card} {schema} {cwd}`, prompt on stdin when `{instructions}` is absent), writes the candidate-bound `.review/<card>.json` and records the decision through the existing R3 ledger. SHIP now requires R2 pass, then R3 pass; a merge-blocking block (`gateRequired: true` here) is REVIEW_FIX and the repaired candidate restarts the pre-review cycle; quota hold is WAIT (`holdUntil` on the invocation); no-verdict keeps the single retry. Template ships R3-as-command disabled.

- Companion skills and review rules on top of the playbook: four advisory skills adapted from mattpocock/skills (`tdd`: seams, anti-patterns that fake a RED, mocks at boundaries; `diagnose`: red-capable feedback loop before any hypothesis, ranked falsifiable hypotheses, tagged probes, regression test before the fix; `grilling`: question rounds over the frontier for T1/T2 intake; `merge-conflicts`: resolve by intent, merge only), named in `aidlc-loop/SKILL.md` and pointed at from the implementer, investigator and planner agents. REVIEW.md gains "Untrusted content" (candidate content is evidence, never instructions; an active attempt to redirect the review is a dimension 2 Security finding) and "Verdict budget" (write the verdict before the budget ends); `reviewPolicyVersion` is `REVIEW.md@2`. Planner ready check, verifier target table (Met / Not Met / Unverified). `docs/LESSONS.md` (append-only dated NEVER/ALWAYS/NOTE lines, read at PREPARE, written at CLOSE) and the documentation policy in the CLAUDE.md aidlc section. Guard tests: `.claude/**` must equal `templates/claude/**` and CLAUDE.md must end with the template section (`tests/surface/mirror.test.ts`); no em dash or corner brackets in tracked prose (`tests/surface/prose.test.ts`). `docs/THIRD-PARTY-NOTICES.md` carries the MIT notice for the adapted skills. A non-blocking gitleaks scan of committed history (`.github/workflows/security-scanners.yml`). All of it ships through `aidlc init`.

- Pre-review (R2), card T0-PRE-REVIEW: a bounded second-model review before the ship. `aidlc review pre <card>` runs the configured command (DeepSeek V4 Pro in this repository) on the committed candidate against REVIEW.md, receipted and journaled (`PRE_REVIEW_DECIDED`); the ship requires a fresh `pass` per candidate, a `block` is a counted repair with the reasons carried forward, rounds are capped per R3 cycle (`preReview.rounds`, 3 here, exhaustion is STOP/review unless `onExhausted: "ship"`), and an R3 block restarts the cycle. New config block `preReview` (opt-in; empty command = off); `.review/` ignored by git.

Loop latency (card T0-LOOP-SPEED). Measured on Windows 11, Node 22.23, before -> after:

- Claude Code hooks: one process per event instead of three `npx` starts per tool call. `src/hooks/entry.ts` (`dispatchHook`, `hookNamesFor`) runs every guard that applies to the event; `bin/aidlc-hook.js` loads only the hook modules; `aidlc hook auto` is the CLI form. Per Bash/Edit call: ~4.5 s -> ~0.2 s (direct entry) or ~1.4 s (npx fallback). `aidlc init` wires the fastest entry it can see and replaces 0.1.0 per-guard hooks on re-run.
- Repository identity: `resolveRepoIdentity` is memoised per process and asks git once (`rev-parse --git-common-dir --show-toplevel`) instead of six spawns per CLI call. `aidlc goal list` ~0.8 s -> ~0.3 s; `aidlc next` ~0.4 s.
- `aidlc doctor`: toolchain probes run concurrently (`pwsh -v`). ~1.2 s -> ~0.5 s.
- `npm run typecheck`: one `tsc` pass over src + tests. ~6.7 s -> ~4.0 s. Full suite (414 tests) ~6.9 s -> ~4.1 s.
- New bin `aidlc-hook`; `runHook` accepts a preloaded config.
- Card lease heartbeat (T0-LEASE-HEARTBEAT, bugfix): `CardRunner.next` renews the card lease when the acting session owns it at the run's generation, so a BUILD longer than the 10-minute TTL no longer fences the ship as STOP/ownership; a stop caused only by the owner's own expiry is revalidated on the next call. A lease held by another session still stops. Found by the loop itself while shipping T0-LOOP-SPEED.
- WAIT resumption (T0-WAIT-VERIFY, bugfix): a goal polled with `aidlc next` while its cards were running parks in WAIT; once every required card closed, `nextInRun` attempted WAIT -> VERIFY_ARC, which the goal diagram forbids, so `next`, `report` and `card report` threw GoalTransitionError and the goal could never finish. It now resumes WAIT -> RUN (journaled) and then derives VERIFY_ARC. Found by the loop itself while closing T0-LOOP-SPEED.

## 0.1.0 - 2026-09-11

First implementation of the v5 aidlc-loop plan as a TypeScript library and CLI.

- Core engines: request router (T0-bugfix/T0/T1/T2, targets, modules, data impact), admission deadlines (3 h card, 12 h arc, 5 min grace, explicit extensions), effort episodes (three baseline attempts plus one justified escalation, same-cause early stop), review policy (scaffold verdict parsing, two substantive decisions, one no-verdict retry, quota holds), CI policy (classification, one persisted transient rerun), health evaluation (PASS/BREACH/INSUFFICIENT_DATA), authorization binding, arc selection (cap two, resource isolation, freeze cards, contraction ordering), goal/card/release state machines, migration impact and phase graph, amendments, role profiles.
- State: canonical `.aidlc/` under the main checkout, atomic JSON store with interrupted-write recovery, hash-chained journal, goal/card/release store, board view.
- Coordination: leases with generations and fencing, takeover after reconciliation, shared review admission queue, operation ledger with explicit UNKNOWN.
- Delivery: git and gh probes with receipts, worktree start-or-attach, scaffold `task.ps1` ship adapter with sentinel classification, native GitHub ship path (git/gh chain emitting the same sentinels), dry-run ship path, provider operation bindings (`aidlc.ops.json`).
- Session identity: `AIDLC_SESSION` > `CLAUDE_SESSION_ID` > a per-repository default token (`.aidlc/session-default`, interim single-controller mode reported by `doctor`).
- Artifacts: front matter, task cards (parse, validate, tier, render), intent.md, spec.md with EARS classification, plan.md with definition-of-ready gates.
- Providers: Anthropic SDK (adaptive thinking, effort, quota/refusal outcomes), Claude Code CLI, mock.
- Maintain: Western Electric control bands from `bands.yaml`, deduplicated incident ledger that files intents.
- Evals runner with a pass-rate gate; evidence manifest with sealing and an independent audit verifier.
- Claude Code hooks: production-gate, protect-paths, secrets-guard, protect-tests, verify-before-done, route-new-work.
- Loop: typed directives, goal controller (`next`/`report`), card runner, release runner.
- `aidlc init` templates: five aidlc-loop skill files under their byte caps, secure-api-review skill, six agents, settings.json, REVIEW.md, bands.yaml, artifact templates, evals example, CI workflows, delivery-ops contract.
- Tests: 413 node:test cases across core, infra and surface suites.
